一个面向 AstrBot 群聊的事件管理插件：记下未来要发生的事，在临近和到点时提醒；也可以记录过去的重要日期，持续展示已经过去的时间。

适合版本上线、活动前瞻、报名截止、聚会安排，以及开服、建群、项目上线等时间记录。群成员可以查看事件卡片，管理员可以通过指令或自然语言管理事件。

**当前支持：** aiocqhttp（OneBot v11） · AstrBot 4.0.0+ · Python 3.10+

**插件标识：** `astrbot_plugin_countdown`。当前插件显示名仍为「倒计时」，指令入口为 `/倒计时`、`/cd` 或 `/countdown`。

[快速开始](#快速开始) · [自然语言管理](#自然语言管理) · [指令参考](#指令参考) · [提醒规则](#提醒规则) · [配置与数据](#配置与数据) · [更新记录](CHANGELOG.md)

## 可以用来做什么

| 用途 | 使用方式 | 示例 |
| --- | --- | --- |
| 关注未来事件 | 为一个具体日期添加倒计时，查看还剩多少天 | 游戏发售、报名截止、新版本上线 |
| 提醒具体时刻 | 为事件填写日期和时刻，接收提前提醒与到点提醒 | 线上观影、活动前瞻、聚会开始 |
| 记录已经过去的时间 | 为一个过去的日期添加正计时，持续累计时长 | 开服天数、建群天数、项目上线天数 |
| 每日查看事件总览 | 在本群设定的时间发送汇总卡片，也可随时手动查询 | 每天早上查看待发生事件和时间记录 |
| 用对话管理事件 | 由 LLM 调用插件工具进行添加、查询、修改、停用和删除 | “把线上观影改到 12 月 31 日 20:30” |

每个群分别保存自己的事件、播报时间和每日汇总开关。私聊默认也可使用，数据与群聊隔离。

事件提醒按单次日期保存；正计时用于记录已经过去的时间。需要每年的生日或周年提醒时，请为下一次纪念日另建具体日期的事件。

## 安装

从 [Releases](https://github.com/cnflwzh/astrbot_plugin_countdown/releases) 下载 `astrbot_plugin_countdown-vX.Y.Z.zip`，在 AstrBot WebUI 插件页通过“从文件安装”上传，然后重载插件。

也可以将仓库放到 `data/plugins/astrbot_plugin_countdown/`，再在插件页重载。

安装后在 WebUI 中完成两项设置：

1. 设置管理员。默认只有 AstrBot 仪表盘管理员能够添加或修改事件，详见[权限](#权限)。
2. 检查插件的时区与默认播报时间，默认分别为 `Asia/Shanghai` 和 `09:00`。

## 快速开始

下面的示例分别创建一个日期事件、一个带时刻的事件和一条时间记录。使用时请换成实际的名称与日期。

```text
/倒计时 添加 新版本上线 2026-12-31
/倒计时 添加 线上观影 2026-12-31 20:00
/倒计时 正计时 小站上线 2024-06-01
```

查看当前群的事件卡片：

```text
/倒计时 查询
```

查看包含停用任务的完整列表，或调整本群每日汇总时间：

```text
/倒计时 列表
/倒计时 时间 09:00
```

每日汇总默认开启。带具体时刻的事件默认提前约 10 分钟提醒一次，到点后再提醒一次；正计时会持续保留。

本文统一使用 `/倒计时`，也可以换成 `/cd` 或 `/countdown`。如果修改过 AstrBot 的唤醒前缀，请相应替换 `/`。

## 自然语言管理

启用 `enable_llm_tools` 后，可以在与 AstrBot 的对话中表达需求，例如：

```text
帮本群记一个事件：2026 年 12 月 31 日 20:00 线上观影。
我们的小站是 2024 年 6 月 1 日上线的，帮我记录已经上线多少天。
把线上观影改到 2026 年 12 月 31 日 20:30。
先停用线上观影的提醒。
发一下本群当前的事件卡片。
```

模型需要实际调用插件工具，操作成功后以工具返回的结果为准。对话管理与斜杠指令使用相同的会话隔离和权限，普通成员不会因为通过模型操作而获得管理权限。

当前提供添加、列表、卡片查询、修改和删除工具。每日汇总时间及开关使用 `/倒计时 时间`、`/倒计时 开启`、`/倒计时 关闭` 设置；提前提醒的分钟数在插件配置中统一调整。

## 指令参考

以下指令作用于当前会话。在群聊中管理本群事件，在私聊中管理该私聊的事件。

默认所有人可以查看列表、查询卡片和查询播报时间；其余管理操作需要管理员权限。

| 指令 | 作用 | 子命令别名 |
| --- | --- | --- |
| `/倒计时 添加 <名称> <日期或日期时间> [模板]` | 添加未来事件 | `add`、`新建` |
| `/倒计时 正计时 <名称> <起始日期> [模板]` | 记录从起始日期至今的时长 | `up`、`countup` |
| `/倒计时 列表` | 查看全部任务、序号与启用状态 | `list`、`ls` |
| `/倒计时 查询` | 立即发送当前可播报任务的卡片 | `播报`、`now`、`query` |
| `/倒计时 改 <序号或名称> <字段> <新值>` | 修改名称、日期、模板或开关 | `编辑`、`edit` |
| `/倒计时 删除 <序号或名称>` | 删除一条任务 | `del`、`delete`、`rm` |
| `/倒计时 开关 <序号或名称>` | 切换一条任务的启用状态 | `toggle` |
| `/倒计时 时间 [HH:MM或默认]` | 查看或设置本群每日汇总时间 | `time` |
| `/倒计时 开启` | 开启本群每日汇总 | `enable`、`on` |
| `/倒计时 关闭` | 关闭本群每日汇总 | `disable`、`off` |
| `/倒计时 帮助` | 查看简要用法，不写子命令也会显示帮助 | `help`、`?` |

### 添加事件与时间记录

名称在前，日期在后，可选模板放在最后。名称可以包含空格，也可以使用引号或 `《书名号》`；书名号后紧接的文字仍属于名称。

```text
/倒计时 添加 《明日方舟：终末地》前瞻 2026年12月31日19:30
/倒计时 添加 "周末 线上观影" 2026-12-31 20:00
/倒计时 添加 报名截止 2026-12-31 距离{name}还有{days}天，记得填写报名表
/倒计时 正计时 社区成立 2024-06-01 {name}已经过去{days}天
```

| 日期写法 | 含义 |
| --- | --- |
| `2026-12-31`、`2026/12/31`、`2026年12月31日` | 指定年月日 |
| `12月31日` | 省略年份；未来事件取今天或下一个未到的该日期，正计时取今天或上一个已经到来的该日期 |
| `2026-12-31 20:00` | 指定日期和时刻 |
| `2026年12月31日20:00` | 日期与时刻也可以连写 |

斜杠指令使用上表中的明确日期格式。只填月日会在创建时确定年份，不会自动变成每年重复的提醒。

未来事件的日期不能早于今天，带时刻时目标时间须晚于现在；正计时的起始日期不能晚于今天。每条名称最多 50 个字符，同一会话内不能重名。

### 查看、修改与删除

`列表` 包含全部任务及停用状态，`查询` 发送当前可播报任务的图片卡片。停用任务和目标日期已过的倒计时不会出现在查询卡片中。图片生成失败或卡片过大时会回退为文字，也可在配置中关闭图片。

卡片序号与列表一致。修改或删除前可以先查看列表，再使用最新序号或准确名称：

```text
/倒计时 列表
/倒计时 改 线上观影 日期 2026-12-31 20:30
/倒计时 改 1 名称 新版本正式上线
/倒计时 改 1 模板 距离{name}还有{remain}
/倒计时 改 1 开关 关
/倒计时 删除 线上观影
```

| 修改字段 | 别名 | 新值 |
| --- | --- | --- |
| `名称` | `名字`、`name` | 新名称 |
| `日期` | `时间`、`date` | 新日期或日期时间 |
| `模板` | `句式`、`template` | 新的播报句式 |
| `开关` | `enabled` | `开` 或 `关` |

改期会重置提前提醒与到点提醒的状态，之后按新时间提醒。

`/倒计时 开关 1` 会在启用和停用之间切换。停用任务保留在列表中，不参与卡片、每日汇总、提前提醒、到点提醒或自动清理。

### 每日汇总时间与开关

```text
/倒计时 时间
/倒计时 时间 21:30
/倒计时 时间 默认
/倒计时 开启
/倒计时 关闭
```

不带参数时查看本群当前时间；填写 `HH:MM` 设置本群时间；`默认`、`default` 或 `reset` 恢复插件默认值。修改本群时间不会影响其他群或 WebUI 中的全局默认。

**关闭每日汇总后，带时刻事件的提前提醒与到点提醒仍会发送。** 如需暂停某个事件的所有自动提醒，请停用该事件。手动查询不受每日汇总开关影响，也不会改变当天的自动播报状态或触发任务清理。

## 提醒规则

默认行为如下，自动清理由 `cleanup_after_zero` 控制：

| 类型 | 如何展示与提醒 | 何时清理 |
| --- | --- | --- |
| 仅有日期的未来事件 | 每日汇总展示剩余天数；当天改成“某事件就在今天！” | 当天汇总发送成功后删除；已过期的日期事件也会自动清理 |
| 带时刻的未来事件 | 每日汇总展示剩余时长；临近时单独发送提前提醒，到点后单独发送到点提醒 | 到点提醒发送成功后删除，即使已经跨日也先完成提醒 |
| 正计时记录 | 每日汇总展示从起始日期至今已经过去的时间 | 持续保留，直到手动删除 |

例如，设置 `2026-12-31 20:00` 的“线上观影”后，默认会经历：

1. 当天的每日汇总显示距离观影还有多少小时、分钟。
2. 约在 19:50 发送文字提醒：“线上观影还有10分钟！”
3. 到 20:00 后发送：“线上观影到时间了！”
4. 到点提醒发送成功后，自动删除该事件。

提醒依赖机器人在线运行。若错过提前提醒窗口、重启时已到目标时间，会直接处理尚未成功发送的到点提醒。每日汇总有独立的补发窗口，默认是 10 分钟；仅日期事件不会补发已经错过的往日汇总。

关闭自动清理后，历史任务会保留在列表中；目标日期已经过去的倒计时仍不会加入查询卡片或每日汇总。

## 卡片与自定义文案

查询和每日汇总默认发送图片卡片，采用浅色布局与大号时间数字。当天事件用暖橙色，正计时用青绿色；长名称和多行文案会自动换行。

卡片同时呈现未来事件和过去时间记录。以上方快速开始的三条任务为例，在 2026 年 12 月 1 日 09:30 查询时，文案为：

```text
今天是2026年12月1日。
- 距离新版本上线还有30天
- 距离线上观影还有30天10小时30分钟
- 小站上线已经过去913天
```

没有填写单独模板时，插件会按任务类型使用 WebUI 中的默认模板：

| 场景 | 默认文案 |
| --- | --- |
| 仅日期的未来事件 | `距离{name}还有{days}天` |
| 带时刻的未来事件 | `距离{name}还有{remain}` |
| 正计时 | `{name}已经过去{days}天` |
| 日期事件到当天，或带时刻事件已经到点 | `{name}就在今天！` |
| 提前提醒 | `{name}还有{minutes}分钟！` |
| 到点提醒 | `{name}到时间了！` |

当事件到期时，卡片使用到期模板，会覆盖该事件原本的自定义文案。

### 模板占位符

播报标题和任务条目都可以使用以下日期占位符：

| 占位符 | 含义 |
| --- | --- |
| `{today}`、`{today_iso}` | 当前日期，如 `2026年12月1日`、`2026-12-01` |
| `{year}`、`{month}`、`{day}` | 年、月、日 |
| `{month_02}`、`{day_02}` | 补零的月、日 |
| `{weekday}`、`{weekday_short}` | 星期几，如 `星期二`、`周二` |
| `{hour}`、`{minute}` | 当前时、分 |
| `{hour_02}`、`{minute_02}` | 补零的时、分 |

任务条目还可以使用：

| 占位符 | 含义 |
| --- | --- |
| `{name}` | 任务名称 |
| `{days}` | 剩余或已过的完整天数 |
| `{hours}`、`{minutes}` | 去掉完整天数后的小时、去掉完整小时后的分钟 |
| `{remain}` | 组合后的剩余或已过时长，如 `2天3小时`、`10小时30分钟` |
| `{target}` | 目标或起始日期，填写了时刻时包含时间 |
| `{target_iso}` | 目标或起始日期的 ISO 表示，如 `2026-12-31` |
| `{target_time}` | 目标或起始时刻，如 `20:00`；仅日期时为空 |
| `{mode}` | `倒计时` 或 `正计时` |

提前提醒模板中的 `{minutes}` 表示配置的提前提醒分钟数。

单条任务的自定义模板最多 200 个字符。支持 `{days:03d}` 等补零格式，以及用 `{{`、`}}` 输出花括号。未识别的普通占位符会原样保留；无效格式按原文显示。

模板不支持对象属性或下标访问。格式宽度、精度和单条展开结果上限为 4096；超长原始模板会截断，避免异常格式影响出图。

## 权限

默认只有 **AstrBot 仪表盘管理员** 能够管理任务、设置本群播报时间或切换每日汇总。

1. 在群里发送 `/sid`，记下自己的 `UID`。
2. 打开 WebUI 的 `配置 → 其他配置 → 管理员 ID`，添加该 UID。

也可以通过插件配置中的 `manage_permission` 调整管理范围。AstrBot 管理员始终保有管理权限。

| 配置值 | 可管理的人 |
| --- | --- |
| `astrbot_admin` | AstrBot 仪表盘管理员，默认值 |
| `plugin_admin` | `plugin_admin_ids` 中填写的用户，以及 AstrBot 管理员 |
| `group_admin` | 当前 QQ 群的群主、管理员，以及 AstrBot 管理员 |
| `all` | 所有人 |

`allow_query_all` 默认开启，允许普通成员查看列表、卡片和播报时间；关闭后这些操作也要求管理权限。私聊中没有 QQ 群管理身份，可使用 AstrBot 管理员或其他适用的权限模式。

## 配置与数据

在 AstrBot WebUI 的本插件配置页调整：

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `timezone` | `Asia/Shanghai` | 日期计算和提醒使用的时区 |
| `broadcast_time` | `09:00` | 每日汇总默认时间，可由各群单独覆盖 |
| `pre_remind_minutes` | `10` | 带时刻事件提前提醒的分钟数；设为 `0` 关闭提前提醒，保留到点提醒 |
| `catch_up_minutes` | `10` | 每日汇总的补发窗口；设为 `0` 仍在设定的播报分钟内发送 |
| `send_image` | `true` | 查询和每日汇总使用图片卡片，关闭后使用文字 |
| `cleanup_after_zero` | `true` | 自动清理已结束的倒计时，具体规则见上文 |
| `enable_llm_tools` | `true` | 允许模型调用插件管理工具 |
| `allow_private` | `true` | 允许在独立私聊中使用 |
| `max_tasks_per_group` | `30` | 每个会话的任务数量上限，停用任务也计入 |
| `at_all_on_zero` | `false` | 每日汇总包含到期事件时尝试 `@全体成员`，需机器人具备相应权限 |

标题、各类型条目、提前提醒和到点提醒的文案也可在配置页分别修改。

数据与插件代码分开保存：

| 内容 | 路径 |
| --- | --- |
| 插件代码 | `data/plugins/astrbot_plugin_countdown/` |
| WebUI 配置 | `data/config/astrbot_plugin_countdown_config.json` |
| 任务数据 | `data/plugin_data/astrbot_plugin_countdown/data.json` |
| 生成的卡片 | `data/plugin_data/astrbot_plugin_countdown/` 下 |
| 启动时同步的 Skill | `data/skills/countdown-manager/SKILL.md` |

升级前可备份配置文件和整个 `data/plugin_data/astrbot_plugin_countdown/` 目录。更新插件代码不需要迁移任务数据。

## 常见问题

### 为什么界面和命令还叫“倒计时”？

README 使用“事件提醒与时间记录”来说明完整用途；当前版本的插件显示名、标识、命令和工具名仍沿用原名称。安装或更新时继续使用 `astrbot_plugin_countdown`，操作时使用 `/倒计时`、`/cd` 或 `/countdown`。

### 关闭每日汇总后，为什么还收到提醒？

每日汇总开关只控制每日卡片。单个事件的提前提醒、到点提醒独立运行；使用 `/倒计时 改 <序号或名称> 开关 关` 可以停用该事件。

### 覆盖安装后提示 `cannot import name ...`

旧版模块或文件可能仍被保留。先备份配置和任务数据，再卸载插件、清理 `data/plugins/astrbot_plugin_countdown/` 中的残留代码，重新安装并重载。

### 提示数据文件损坏或无法读取

插件会停止写入并保留原文件。修复 `data.json` 或恢复备份后，再重载插件。

### 模型找不到 `countdown-manager` 的 Skill 文件

插件启动时会同步 `skills/countdown-manager/SKILL.md`，供 AstrBot 扫描。沙盒中的 `/workspace/skills/` 不一定能看到这份文件；模型可以直接调用已注册的 `countdown_*` 工具，无须先从磁盘读取 Skill。

当前提供的工具如下：

| 工具 | 用途 |
| --- | --- |
| `countdown_add` | 添加事件或正计时记录，`mode` 为 `countdown` 或 `countup` |
| `countdown_list` | 查看当前会话的完整列表和序号 |
| `countdown_query` | 发送当前会话的卡片并返回文字摘要 |
| `countdown_edit` | 修改名称、日期、模板或启用状态 |
| `countdown_delete` | 按序号或准确名称删除 |

如需在对话中使用，请开启 `enable_llm_tools`，并允许当前模型调用相关工具。

## 开发与打包

在仓库根目录执行：

```bash
python -m ruff format main.py countdown tests
python -m ruff check main.py countdown tests
python -m pytest tests
python pack.py
```

安装包生成在 `dist/`，ZIP 根目录必须为 `astrbot_plugin_countdown/`，可直接用于 WebUI 从文件安装。

```bash
python pack.py --include-tests
python pack.py -o D:\tmp\countdown.zip
```
